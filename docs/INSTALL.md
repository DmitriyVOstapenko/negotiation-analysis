# Установка и первый запуск

## Что нужно

- Claude Code, Cowork или проект claude.ai.
- Python 3.10 или новее, команда `python3` в `PATH` (на Windows — `python`; скрипты
  вызываются так, как указано в навыках, при необходимости замените имя команды).
  Проверка: `python3 --version`.
- Внешних библиотек не нужно. Интернет не нужен — кроме отправки себе в Telegram, если вы её
  включите.

## Claude Code

```
/plugin marketplace add DmitriyVOstapenko/negotiation-analysis
/plugin install negotiation-analysis@negotiation-analysis-marketplace
```

Перезапустите Claude Code. Откройте папку, в которой будет жить база (любую пустую или уже
существующую с `knowledge/`), и напишите: «Проанализируй встречу» + транскрипт.

## Cowork

Примите файл `negotiation-analysis.plugin` из чата (кнопка принятия) или установите плагин из
каталога организации. Подключите к задаче папку, где будет база. Всё остальное — словами.

## Проект claude.ai

Установите плагин так же. В проекте база хранится документами проекта с путями
`knowledge/...`, `negotiations/...`, `profile/...`. Первый разбор создаст их. Дальше любой
чат проекта видит ту же базу.

Проверено: сессии Cowork/Claude Code, привязанные к проекту. В обычном чате проекта
возможности могут отличаться — если навык сообщает, что документы проекта недоступны, он
работает в режиме «только разговор» и скажет об этом.

## Что работает где

Кроме навыков и скриптов, в плагине есть три агента (`agents/`) и хук защиты базы (`hooks/`).
Хосты поддерживают их по-разному; всё, что делают агенты и хук, имеет текстовый путь в самих
навыках, поэтому без них система работает, только медленнее и без внешней страховки.

| Возможность | Claude Code | Cowork | Проект claude.ai (чат) | Codex — по внешним замерам, не проверено нами |
|---|---|---|---|---|
| Навыки | да | да | да | да: читает `.claude-plugin/plugin.json` |
| Скрипты `na.py` | да, через Bash | да (облачный режим — см. ниже) | нет — текстовый путь | если есть оболочка |
| Подстановка пути к плагину | только в текст навыков и агентов | как в Claude Code | — | нет: переменная остаётся как есть |
| Агенты `transcript-analyst`, `evidence-verifier`, `reader` | да | по внешним замерам — да | нет | нет: агентов плагина Codex не загружает |
| Хуки: защита базы и ответ владельца | да | только если хук видит папку | нет | хуки типа command — после доверия пользователя; разбор apply_patch есть, не проверен |
| Длинная встреча по частям, режим с верификацией | да | если есть агенты | последовательно и самопроверкой | текстовым путём |

**Claude Code.** Путь к плагину (`${CLAUDE_PLUGIN_ROOT}`) Claude Code подставляет только в текст
навыков и агентов; в командах Bash эта переменная пуста, поэтому навыки объясняют, как найти корень
плагина. Агенты вызываются как `negotiation-analysis:transcript-analyst`,
`negotiation-analysis:evidence-verifier`, `negotiation-analysis:reader`. У агента `reader`
инструментов нет вовсе: в списке агентов Claude Code для него показывает «All tools», но при запуске
инструментов у него нет (проверено).

Хук срабатывает перед записью файлов — инструментами правки (Write, Edit, NotebookEdit; MultiEdit
старых версий), командами оболочки (Bash, PowerShell) и заплаткой `apply_patch` — и только внутри
рабочей папки системы: прямая запись, правка и удаление в `knowledge/` запрещены с объяснением
«только через knowledge-update», правка и удаление `negotiations/<id>/transcript.txt` и заметки
провайдера, каталога встречи и самой рабочей папки запрещены, запись стратегической карточки в
`knowledge/strategies/` требует подтверждения пользователя. Цели записи в команде оболочки он
находит эвристикой (перенаправления, `tee`, `sed -i`, `cp`/`mv`/`rm`, `python -c`, heredoc и др.):
запись через переменную или отдельный скрипт он не видит. Скрипты `na.py` пишут в базу сами — это
законный путь, хук их не трогает.

Второй рубеж — ответ владельца. Команды `na.py`, которые фиксируют его решение (`knowledge apply
--confirm`, `knowledge decide`, `source gate`, `speakers set`, `review record`, `review confirm`,
`deliver send --confirm`, `deliver record --status sent`, `deliver telegram-link --confirm`, `migrate
--confirm`), проходят, только если последняя реплика человека в сессии (или его ответ на вопрос с
вариантами) содержит согласие — «да», «применяй», «подтверждаю», «отправляй», «верно» и т. п. — без
«нет», «подожди», «сначала …», а для применения и отправки — прозвучала после показа (diff,
предпросмотр). Иначе команда отклоняется с причиной «это решение владельца: спросите его и
выполните после ответа». Если транскрипт сессии не читается, хук не судит (пропускает).

Хуку нужна команда `python3`: если её нет (бывает на Windows), Claude Code покажет уведомление
«hook error», запись не блокируется, и база защищена только правилами навыков. Проверено нами в
Claude Code 2.1.303: запись в `knowledge/people/…` — инструментом Write и командой `echo … >` —
остановлена; `report.md` встречи и файлы вне рабочей папки записаны; правка `transcript.txt`
остановлена; стратегическая карточка без подтверждения не записана; `knowledge apply --confirm`
без согласия в реплике отклонён, после «Да, применяй» — выполнен.

**Cowork.** Плагин тот же. По внешним замерам (сентябрь 2026; нами не проверено): хуки в Cowork
работают только из плагина, а режимов исполнения два. В облачном режиме плагин, хуки и скрипты
исполняются в контейнере, а подключённая папка остаётся на компьютере пользователя за мостом,
которым пользуется только модель: хук не видит папку и пропускает всё, скрипты работают с копией
данных в сессии. В режиме «Only on this computer» хук исполняется на компьютере пользователя, его
рабочий каталог — служебная папка сессии; защита срабатывает, только если путь в вызове инструмента
виден с этого компьютера. Агенты — по внешним замерам события запуска агентов в Cowork наблюдались.
Где хука или агентов нет, правила навыков действуют как прежде.

**Проект claude.ai (обычный чат).** Хуков, агентов и Bash к скриптам нет. Навыки работают
текстовым путём: проверку читателем ассистент делает сам, не заглядывая в источники; длинную
встречу читает последовательно кусками; вместо независимой проверки — самопроверка с пометкой
«не независимая»; база меняется только после показанного изменения и подтверждения.

**Codex (по внешним замерам, не проверено нами).** Codex читает `.claude-plugin/plugin.json` как
формат совместимости и загружает навыки и `hooks/hooks.json` (только хуки типа command, каждый — после
того, как пользователь ему доверится). Переменную пути к плагину в тексте навыка Codex не
подставляет — навыки находят корень плагина от каталога навыка. Агентов плагина Codex не загружает:
длинные встречи и верификация идут текстовым путём. Файлы Codex правит заплаткой `apply_patch`:
хук умеет достать из неё пути, но на живом Codex это не проверено; формат транскрипта Codex хук
тоже читает по описанию, без проверки.

## Первый запуск

1. Скажите: «Проанализируй встречу» и вставьте транскрипт (лучше с таймкодами и метками
   спикеров) или укажите файл.
2. Ответьте на шесть вопросов шлюза (право на обработку, конфиденциальность, категории
   данных, маскирование, маршрут, хранение).
3. Подтвердите карту спикеров.
4. Получите один экран и, при желании, детали.
5. Скажите «Применяй изменения базы» — только тогда база обновится.
6. Спросите «Что требует моего решения?» — увидите очередь.

## Профиль (по желанию)

Создайте в корне базы `profile/role.yaml`, `organization.yaml`, `policy.yaml` по образцам из
`profiles/examples/` (замените примерные имена и названия на свои) или попросите систему
предложить профиль. Профиль уточняет приоритеты экрана и словарь ролей, но не может ослабить
согласие и доказательность.

## Проверка работоспособности

Быстро и без сети — самопроверка установки и рабочей папки:

```
python3 <путь к плагину>/scripts/na.py --root <корень базы> doctor --probe
```

Она сообщает версию Python и какие команды его запускают (`py -3`, `python3`, `python`), сверяет
файлы с паспортом сборки, проверяет хуки, агентов, версию схемы базы, защиту ключа бота и есть ли
рядом плагин Ивана. Полный прогон тестов:

```
python3 <путь к плагину>/tests/run_tests.py
```

Сквозной тест на синтетической встрече: регистрация → шлюз → валидация → отчёт →
follow-up → проект изменений → применение → контрольный центр. Все проверки должны пройти.
В том же прогоне проверяются хук защиты базы, синтаксис агентов и `hooks/hooks.json`, части
длинной встречи и отчёт верификации.

Проверить сам хук вручную (Linux, macOS; ожидается JSON с `"permissionDecision": "deny"`, для пути
вне базы — пустой вывод):

```
echo '{"hook_event_name":"PreToolUse","tool_name":"Write","tool_input":{"file_path":"<корень базы>/knowledge/people/x.md"}}' | python3 <путь к плагину>/hooks/guard_writes.py
```

## Отправка себе в Telegram и на почту (по желанию)

Почта: скажите «мой адрес для отправки себе — …» (команда `deliver setup --email`); письма
создаёт подключение Gmail, по умолчанию — черновиком себе. Telegram: создайте бота у @BotFather,
передайте ключ (`deliver setup --telegram-token-stdin`), напишите боту «Старт» и привяжите свой
чат (`deliver telegram-link`). Пошагово — `skills/negotiation-system/references/delivery.md`.

## Рядом с плагином «Иван»

Если у вас установлен плагин Ивана (coman-ivan), на время работы с переговорами выключите его:
Customize → Plugins. Почему — `docs/IVAN.md`.

## Обновление

Claude Code: `/plugin update negotiation-analysis@negotiation-analysis-marketplace`. База
пользователя при обновлении плагина не затрагивается — она живёт отдельно. После обновления
до 0.6.0 выполните `na.py migrate` (покажет план) и `na.py migrate --confirm` — версия схемы базы
будет зафиксирована.

## Советник Negociar-RU

Встроен в плагин (навык `negociar-ru`): ставить отдельно ничего не нужно, Node.js не нужен —
поиск по случаям на Python. Проверка: `python3 skills/negociar-ru/scripts/buscar.py "долг клиент"`
из каталога плагина должен вывести список случаев. Оригинал на испанском
(`arturgaliev3099-ux/realmanagement`) для работы не требуется.
