# Установка и первый запуск

## Codex desktop — основная среда

Версия 0.8.0 подготовлена локально; живая установка и активация ещё требуют проверки.
Нужен Codex desktop с выполнением локальных команд и Python 3.10 или новее.
На Windows должна работать команда `python`, на macOS/Linux — `python3`.
Git Bash для проверок Codex не требуется. Внешних библиотек Python для основного движка нет.

1. Установите локальный пакет плагина доступным в вашей версии Codex способом.
   В корне пакета должны быть `.codex-plugin/plugin.json`, `skills/`, `hooks/` и `scripts/`.
2. Отдельно просмотрите и разрешите защитные проверки плагина. Установка сама их не разрешает.
   После изменения определения проверки снова проверьте её статус доверия.
3. Начните новый чат с подключённой отдельной папкой для базы переговоров.
   Не используйте для личных встреч публичный репозиторий разработки.
4. Выполните самопроверку и проверку записи, описанные ниже.
5. Передайте транскрипт и задачу. Сначала помощник уточнит условия его обработки.

Манифест Codex ссылается на `hooks/codex.json`; конфигурация Claude в `hooks/hooks.json`
сохранена отдельно. Для Windows используется `commandWindows` с `python`.
Подробные правила исполнения — [CODEX.md](CODEX.md).

Согласно [документации OpenAI](https://developers.openai.com/plugins/build/plugins),
пакеты с lifecycle hooks устанавливаются вручную в Codex desktop и пока не подходят
для общего каталога плагинов. Публичный GitHub-репозиторий не равен публикации в этом каталоге.

## Проверка работоспособности

В PowerShell на Windows:

```powershell
python "<путь к плагину>/scripts/na.py" --root "<корень базы>" doctor --probe --host codex
```

На macOS/Linux замените `python` на `python3`. Самопроверка читает файлы без сети;
проверяет Python, конфигурацию защиты, процедуры агентов, версию базы и паспорт сборки.
Паспорт есть у собранного пакета; в рабочем репозитории его может не быть.
Параметр `--host auto` выбирает Codex при наличии его манифеста, иначе — Claude.
Для проверки сохранённого адаптера Claude используйте `--host claude`.

С `--probe` Codex-команда запускается сначала с пустым событием, затем с синтетической
попыткой прямой записи в базу через `apply_patch` во временной папке. Ожидается отказ.
Так заглушка Python с кодом выхода 0 не выдаётся за работающую защиту.
Это отдельный запуск процесса. Он не доказывает, что Codex загрузил и разрешил проверку.

Живую защиту проверяют в отдельной тестовой базе с синтетическими данными:

- попытка прямой записи в `knowledge/people/…` должна быть отклонена;
- запись отчёта встречи должна быть разрешена;
- изменение зарегистрированного исходного транскрипта должно быть отклонено;
- `knowledge apply --confirm` без ответа владельца должно быть отклонено, если проверка
  смогла прочитать транскрипт сессии;
- после показа diff и явного подтверждения владельца применение должно пройти.

Если событие или транскрипт недоступны, защита может пропустить действие.
Она не заменяет правила навыков: ни модель, ни другая инструкция не могут подтверждать
изменения базы вместо владельца. Разбор команд эвристический; вычисляемые пути
и отдельные скрипты могут быть не видны проверке.

Полный локальный прогон на синтетических данных:

```powershell
python "<путь к плагину>/tests/run_tests.py"
```

Тесты движка и защиты не заменяют содержательный разбор встреч новой моделью.
Реестр проверочных встреч и критерии — [EVALS.md](EVALS.md).

## Что работает где

| Возможность | Codex desktop | Claude Code | Cowork / проект claude.ai |
|---|---|---|---|
| Навыки | компактные входные файлы и подробные процедуры | тот же состав навыков | зависит от доступных возможностей хоста |
| Скрипты `na.py` | локальные команды с проверенным Python | локальные команды | если есть выполнение кода; иначе текстовый путь |
| Защита базы | `hooks/codex.json`, только после доверия и при видимых файлах | `hooks/hooks.json`, Bash | зависит от доступа проверки к рабочей папке |
| Процедуры из `agents/` | передаются доступному помощнику явно; автоматически не считаются загруженными | определения агентов Claude | зависит от поддержки агентов |
| Независимая верификация | только с отдельным контекстом проверяющего | агент `evidence-verifier` | при отсутствии отдельного проверяющего — самопроверка с явной пометкой |

Наличие инструментов делегирования определяется в текущей сессии. Если их нет,
длинную встречу разбирают последовательно. Самопроверку нельзя назвать независимой проверкой.
Маршрут обработки и согласие владельца сохраняются в любой среде.

## Совместимость с Claude

Claude Code:

```
/plugin marketplace add DmitriyVOstapenko/negotiation-analysis
/plugin install negotiation-analysis@negotiation-analysis-marketplace
```

Защитные проверки Claude используют `hooks/run-python.sh`: Python 3.10+ выбирается
из `python3`, `python`, `py -3`. На Windows требуется Git Bash.
Новый запуск в этой среде после перехода на 0.8.0 требует отдельной проверки.

Cowork: установка локального `.plugin` и подключение папки, если эти возможности
доступны в вашей версии. При облачном выполнении проверка может не видеть папку
на компьютере. В таком случае она не обеспечивает защиту записи в эту папку.

Проект claude.ai: при наличии инструментов документов проекта канонические файлы
хранятся документами проекта с теми же путями. Если доступа нет, используется
режим «только разговор». Возможности папки, оболочки и агентов не предполагаются автоматически.

## Первый запуск и профиль

Скажите «Проанализируй встречу» и передайте транскрипт. До анализа требуется решение
по праву обработки, конфиденциальности, маскированию, маршруту и хранению источника.
Карта спикеров и запись изменений базы подтверждаются отдельно.

Профиль `profile/role.yaml`, `organization.yaml`, `policy.yaml` необязателен.
Он уточняет роль и словарь; согласие и доказательность не ослабляет.
Личные данные и настройки находятся в базе пользователя, вне публичного репозитория.

## Отправка себе

Отправка — только владельцу после предпросмотра и явной команды «отправить».
Telegram использует своего бота; ключ не входит в репозиторий.
Почта работает только через доступное подключение Gmail, по умолчанию — черновиком.
Без подключения помощник сообщает, что отправка недоступна.
Подробности — `skills/negotiation-system/references/delivery.md`.

## Другие плагины

Иван не требуется для работы. Если он установлен и его инструкции мешают разбору,
отключите его на время работы. Публичный плагин не меняет чужую установку.
Личная настройка совместимости решается отдельно. См. [IVAN.md](IVAN.md).

## Обновление

Обновите локальный пакет, проверьте доверие защитным проверкам и начните новый чат.
База находится отдельно от установленного плагина. Переход хоста сам по себе не меняет её схему.
Если `doctor` требует миграции, сначала покажите план `na.py migrate`; применение
`na.py migrate --confirm` — только после подтверждения владельца.

Для Claude Code сохранена команда:
`/plugin update negotiation-analysis@negotiation-analysis-marketplace`.
