# Рядом с Иваном

Иван — плагин Максима Опилкина (github.com/Coman-os/ivan, MIT). Он задаёт помощнику характер: уточнять,
решать вычислимое самому, возражать. Его проверки работают в каждой сессии, где он включён. Включить или
выключить плагин для одной папки или проекта в приложении Claude нельзя — только для всего аккаунта.

## Решение владельца (2026-10-19)

Перед работой с переговорами Ивана выключают: Customize → Plugins → Иван → выключить. После работы
включают обратно. Отдельной сборки Ивана с выключателем по папке не делаем.

## Почему не вместе

- **Подталкивание «реши сам».** Проверка окончания ответа (check_closing_handoff) требует решать
  самому вместо вопроса. В разборе переговоров вопросы владельцу законны и обязательны: согласие на
  обработку, карта спикеров, сомнительные пункты учёта, применение изменений базы, отправка себе.
  Действие вместо вопроса ломает доказательность.
- **Проверки оформления .md** (post_write_md_check). Требуют карточку в начале каждого .md. Модель
  может вставить её в черновик письма или в сырую заметку источника, а источник неизменяем.
- **Копии хвостов ответов.** Проверка окончания отдаёт последние до 700 символов ответа отдельному
  вызову модели. Этот текст остаётся в локальном журнале сессий на машине. При разборе настоящих встреч
  там окажутся цитаты и имена.
- **Объём контекста.** Правила Ивана — около 90 КБ — загружаются в каждую сессию.

## Если Иван всё-таки включён

Плагин не ломается и защищает себя сам:

- **Хук `guard_writes.py` закрывает прямую запись.** Нельзя записать в `knowledge/` и в исходные материалы
  встречи напрямую: ни инструментами правки, ни командами оболочки, ни `apply_patch`.
- **Решения владельца проверяются по его реплике.** Перед командами, которые фиксируют его решение —
  `knowledge apply --confirm`, `source gate`, `speakers set`, `knowledge decide`, `deliver send --confirm`
  и другими, — хук проверяет последнюю реплику человека. Явного согласия нет — команда не выполняется,
  кто бы ни подталкивал модель.
- **Решения владельца остаются вопросами** (навык `negotiation-system`, §8 и §11): шлюз, карта спикеров,
  сомнительные пункты учёта, применение, отправка. Вопросы задаются одним блоком с вариантами, а
  действие вместо вопроса запрещено, даже если соседняя проверка требует решать самому.
- **Модель напоминает одной строкой.** Если в контексте сессии есть правила Ивана, модель говорит: «Иван
  включён — для работы с переговорами его лучше выключить».
- **`na.py doctor` сообщает, что плагин Ивана установлен рядом.** Включён ли он в этой сессии, по файлам
  не видно.

## Что взято из Ивана

Код и идеи взяты по лицензии MIT, © 2026 Maxim Opilkin; полный текст — `licenses/third-party/ivan-MIT.txt`:

- `tools/secret_scan.py` — сканер секретов, добавлен шаблон ключа бота Telegram;
- `hooks/_na_hooklib.py` (им пользуются хуки `guard_writes.py` и `guard_decisions.py`): грамматика заголовков
  заплатки `apply_patch` — по `_host_adapter.py`; построчное чтение транскрипта сессии в формах Claude Code
  и Codex — по `_transcript_io.py`; резервные регулярные выражения целей записи в команде оболочки — по
  `WRITE_RE` из `post_bash_write_relay.py` (расширены). Уведомление MIT — целиком в заголовке файла;
- идеи самопроверки по ступеням, паспорта сборки (`BUILD-MANIFEST.json`) и пробы интерпретатора
  (`na.py doctor`);
- правило подсказок субагентам: их правила вставляются прямо в текст агента, со старшинством.
