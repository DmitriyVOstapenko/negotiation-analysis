# Архитектура

## Главный принцип — четыре зоны не смешиваются

1. **Устанавливаемый универсальный продукт** — этот репозиторий: навыки, онтология,
   контракты, скрипты, шаблоны, синтетические тесты. Без данных конкретных людей.
2. **Отдельно лицензируемые методические модули** — Negociar (CC BY-NC-SA 4.0, свой
   репозиторий); будущий собственный «Контур диалога». Обнаруживаются во время выполнения.
3. **Приватные профили и накопленные данные пользователя** — `profile/`, `negotiations/`,
   `knowledge/` в его папке или проекте. Никогда не входят в продукт.
4. **Внешние провайдеры и их учётные данные** — PLAUD, WonderScribe, локальная
   транскрипция; ключи только в переменных окружения; аккаунты в поставку не входят.

## Логические слои

| Слой | Где в репозитории | Что делает |
|---|---|---|
| Evidence core | `core/contracts/`, `scripts/na.py validate` | SourcePacket, SHA-256, цитаты, таймкоды, классы утверждений, уверенность, буквальная проверка цитат |
| Ontology and contracts | `core/ontology/core.ontology.yaml`, `core/contracts/*.json`, `core/ontology/profile.schema.json` | Единый словарь сущностей и 11 исполняемых контрактов анализа; профили добавляют роли и словарь организации, не меняя смысла сущностей |
| Ingestion | `scripts/na.py source …`, `skills/negotiation-system/references/privacy-gate.md` | Шлюз согласия, регистрация источника, дедупликация, карта спикеров |
| Analysis workflows | `skills/meeting-analysis/`, `scripts/na.py validate/report/followup` | 8 артефактов + 3 производных, отчёт с одним экраном, follow-up `draft_not_sent` |
| Memory and projections | `skills/knowledge-update/`, `scripts/na.py knowledge …/refresh-all` | proposal → diff → подтверждение → запись; append-only журнал событий; пересобираемые `system/` |
| Executive workflows | `skills/control-center/`, `skills/executive-briefing/` | Контрольный центр, очередь решений, брифинг, обзоры, board pack, поддержка решения |
| Strategic advisory | `skills/conversation-strategy/` | Общий интерфейс стратегии; внешний модуль с собственным provenance |

## Источники истины

1. `negotiations/` — материалы и подтверждённый разбор каждой встречи;
2. `knowledge/` — актуальное накопительное состояние;
3. `profile/` — роль, организация, политики пользователя;
4. `review.yaml` — решения и подтверждения пользователя по встрече;
5. `core/ontology/` и `core/contracts/` — допустимые сущности, поля, значения.

`system/` — только пересоздаваемый слой (контрольный центр, очередь, поиск). Он не заменяет
канонические источники и не хранится в проекте claude.ai.

## Поток

```
источник → шлюз согласия → SourcePacket (sha256, сегменты, спикеры)
  → review.yaml (карта спикеров, границы) → 11 JSON по контрактам → validate (схема + цитаты)
  → report_auto.md → report.md (факты / интерпретации / подтверждения) → follow-up (draft_not_sent)
  → knowledge_proposal.json → knowledge_diff.md → подтверждение → knowledge apply
  → ledger.jsonl (append-only) → refresh-all (очередь, проекция, поиск, контрольный центр)
  → брифинг следующей встречи
```

## Хранилище в трёх режимах

Одна и та же раскладка путей; отличается только носитель:

- **папка** (Claude Code, Cowork) — скрипты работают напрямую;
- **проект claude.ai** — канонические файлы являются документами проекта с теми же путями;
  локальная рабочая копия `na-workspace/` на время разговора; встреча хранится как
  `analysis_bundle.json` + `report.md` + `review.yaml` + `meta.yaml` (+ транскрипт, если
  шлюз разрешил хранение);
- **только разговор** — без накопления, результаты в тексте.

Правила выбора и синхронизации — `skills/negotiation-system/references/store-adapter.md`.

## Инварианты

1. Сырые источники не изменяются после фиксации границ анализа.
2. Любой поведенческий вывод содержит цитату, таймкод и уверенность.
3. Подтверждение пользователя не выдаётся за фразу из транскрипта.
4. Производное представление можно удалить и полностью пересобрать.
5. Один идентификатор обязательства или риска не может одновременно находиться в активном и закрытом состоянии.
6. Ручные пометки `(m)` не перезаписываются автоматически.
7. Ошибка схемы или ссылка на отсутствующую сущность блокирует статус `ready`; информационный пробел — не блокирует.
8. Открытый вопрос и незавершённый анализ — разные состояния.
9. Аудиометрики не используются как детектор лжи, намерений или манипуляций.
10. Контрольная дата не заменяет исходный срок обязательства.
11. Память меняется только после показанного diff и явного подтверждения.
12. Follow-up и проекты сообщений всегда `draft_not_sent`.

## Приоритет настроек

Безопасность и лицензии → явное решение пользователя по конкретному источнику → политика
организации → ролевой профиль → универсальные значения по умолчанию. Профиль не может
ослабить согласие, доказательность или лицензионные ограничения.

## Два контура распространения

**Универсальный дистрибутив** (этот репозиторий): код, навыки, схемы, пустые шаблоны,
синтетические тесты, документация.

**Приватный рабочий каталог** пользователя: конфигурация, профиль организации, источники,
накопленные знания, журналы, производные. Не публикуется.

## Правило миграции

Архитектурные изменения внедряются добавлением нового слоя рядом с текущим. Массовая
перезапись `knowledge/` допускается только после резервной копии, автоматической сверки
количества и идентификаторов сущностей, сравнения всех пометок `(m)`, проверки на
существующих встречах и явного отчёта о различиях.
