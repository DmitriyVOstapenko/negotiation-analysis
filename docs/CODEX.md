# Выполнение в Codex

## Для кого

Для Codex, выполняющего навыки плагина, и разработчика адаптера. Методика анализа и форматы
данных остаются в навыках, схемах и полных процедурах `references/workflow.md`.

## Пути и команды

Корень плагина `PLUGIN` определяется по расположению входного `skills/<имя>/SKILL.md`:
два уровня вверх от каталога навыка. Корень приватных данных `ROOT` — отдельная папка
пользователя. Не создавать базу в публичном исходном репозитории.

В примерах полных процедур заменить `${CLAUDE_PLUGIN_ROOT}` и `<корень плагина>` на абсолютный
путь `PLUGIN`. В Codex подстановка переменной в тексте навыка не предполагается.
Команды не копируются с неразрешёнными переменными. Пример Windows PowerShell:

```powershell
python "C:\путь к плагину\scripts\na.py" --root "C:\приватная база" doctor --host codex --probe
```

Сначала проверить выбранный Python: `python -c "import sys; print(sys.version)"` на Windows,
`python3 -c "import sys; print(sys.version)"` на macOS/Linux. Нужна версия 3.10 или новее.
Если команда недоступна, проверить `py -3` или другой установленный Python. Использовать
проверенный интерпретатор во всех командах процедуры. Наличие имени команды не доказывает запуск.
При отказе прав остановить затронутое действие и сообщить причину; не обходить отказ.

Относительные ссылки и пути к справкам разрешаются от каталога содержащего их файла.
У перенесённого `references/workflow.md` это каталог `references/`, не каталог входного навыка.
Пути команд разрешаются по явно заданным `PLUGIN` и `ROOT`.
Пути `knowledge/`, `negotiations/`, `profile/`, `system/`, `advice/` относятся к `ROOT`.
Скрипты, шаблоны, схемы, канон и библиотека случаев относятся к `PLUGIN`.

## Помощники и длинные встречи

Файлы `agents/*.md` содержат процедуры; наличие этих файлов не регистрирует помощников в Codex.
Если доступен механизм отдельных помощников, передать им соответствующую процедуру и только
нужный материал. Не требовать имён инструментов Claude: использовать реально доступные средства.
Согласие на обработку, карта спикеров, решения по учёту, применение базы и отправка остаются
у главного помощника и пользователя. Помощникам не передавать право применять базу или отправлять.

Для длинной встречи выполнить `parts plan --meeting <id>`. По плану создавать артефакты частей
по процедуре `agents/transcript-analyst.md`. Затем `parts check --meeting <id>` и только после
успешной проверки `parts merge --meeting <id>`. Форматы и дополнительные параметры —
`scripts/na.py --help`, `parts --help`, `docs/SCRIPTS.md` и полный порядок навыка.

Если отдельных помощников нет, обрабатывать части последовательно в текущей сессии.
Это последовательный анализ, а не независимая проверка. Процедуру проверяющего из
`agents/evidence-verifier.md` можно использовать для дополнительной проверки, но её результат
не объявлять независимым. Если пользователь запросил независимую проверку, а отдельный
контекст недоступен, сообщить ограничение и оставить этот этап невыполненным.
Проверка понятности по `agents/reader.md` также помечается как самостоятельная, если отдельного
читателя нет. Результаты сохраняются и проверяются теми же командами `verification check` и `validate`.

## Защита базы

Codex-манифест `.codex-plugin/plugin.json` выбирает `hooks/codex.json`. На Windows обработчик
вызывается через `python`, на macOS/Linux — `python3`. Bash для этого пути не нужен.
Обработчик принимает команды оболочки и `apply_patch`, защищает базу и исходники встречи,
проверяет ответ владельца перед командами, фиксирующими его решение.

Правила не превращают обработчик в изолированную систему безопасности: разбор команд
эвристический; неизвестный формат или ошибка могут привести к пропуску. Работа через отдельные
скрипты и вычисляемые пути не покрыта полностью. Основной порядок остаётся обязательным:
предложение → показ изменений → ответы по сомнительным пунктам → подтверждение → применение.

Установка плагина не означает доверия его обработчикам. Пользователь проверяет и разрешает
их в настройках приложения; после изменения определений доверие нужно проверить снова.
`doctor --host codex --probe` проверяет файлы, запуск команды и отказ на синтетическую запись
в отдельном временном каталоге. Заглушка Python с нулевым кодом без ответа проверки не проходит.
Без `--host` выбирается Codex, если есть его манифест; для Claude явно указать `--host claude`.
Этот запуск отдельным процессом не подтверждает,
что Codex вызвал обработчик. Для этого нужна попытка запрещённой прямой записи в отдельной
синтетической базе через установленный плагин. До наблюдения такого события не говорить
«защита включена и работает».

## Установка и распространение

Пакет предназначен для ручной установки в настольном Codex с локальным выполнением команд.
Публичный GitHub-репозиторий и каталог плагинов OpenAI — разные способы распространения.
Наличие GitHub-репозитория не означает публикацию в каталоге. Пакеты с такими обработчиками
не предназначены для подачи в публичный каталог без отдельной переработки.
Чужие плагины не обязательны. Их настройки этот проект не изменяет.

## Источники и контекст

Основание адаптации: решение Дмитрия в чате 2026-11-07 перейти с Claude Code на Codex.
Официальные описания формата и событий:
[упаковка плагинов](https://developers.openai.com/plugins/build/plugins),
[обработчики Codex](https://learn.chatgpt.com/docs/hooks).

Проверки: компактность всех входных навыков; наличие полных процедур; события Codex и Claude;
отказ без согласия; согласие после показа изменений; запуск выбранной команды; синтетический
цикл движка. Эти проверки не заменяют прогон реальной встречи в приватной папке.
