# Промпты аналитического разбора

> Эти промпты задают **метод** анализа: на что смотреть, что считать доказательством, какие
> ограничения соблюдать. **Формат выходных файлов задаёт контракт** — см. `contracts-map.md`
> и `core/contracts/contracts.schema.json`. Там, где JSON в промпте отличается от контракта
> (например, `confidence: high/medium/low` в промпте и `certain/probable/possible/speculative`
> в контракте), применять контракт. Все имена, организации, суммы и события в примерах —
> синтетические.

## Восемь аналитических промптов

Общие принципы для всех промптов (не повторяются в каждом шаблоне отдельно, но встроены в текст):
- Схема **Роль → Контекст → Задача → Формат → Ограничения**.
- **Anti-hallucination правило**: любое утверждение в выводе обязано ссылаться на цитату (`quote`) и `timestamp` из входного транскрипта. Если модель не находит достаточных оснований — поле помечается `null`/`"неопределённо"`, а не придумывается.
- Вход — транскрипт в формате `[HH:MM:SS] Speaker N: текст`.
- Выход — валидный JSON без пояснительного текста вокруг (для детерминированной проверки по контракту).

### B.1. Speaker attribution (сопоставление Speaker N → ФИО/роль)

**Промпт:**

```
РОЛЬ:
Действуй как лингвист-эксперт по идентификации говорящих в расшифровках деловых переговоров, специализирующийся на анализе русской разговорной речи.

КОНТЕКСТ:
Тебе передан транскрипт деловой встречи/переговоров с таймкодами и обезличенными метками спикеров (Speaker 1, Speaker 2, ...), полученный через систему транскрибации. Метки спикеров назначены автоматически и могут быть нестабильны (один человек иногда помечен разными номерами). Тебе нужно предложить идентификацию каждой метки, используя:
— прямые самопредставления ("Меня зовут...", "Я представляю компанию...", "С этой стороны...");
— обращения других участников по имени ("Иван, а что скажете по срокам?");
— косвенные признаки роли (упоминание должности, зоны ответственности, характерная лексика — юридическая/финансовая/техническая);
— контекст встречи (кто сторона-заказчик, кто исполнитель).

ЗАДАЧА:
1. Пройди по всему транскрипту и для каждой уникальной метки Speaker N определи наиболее вероятные ФИО (или, если ФИО не названо, — роль/должность/сторону: "представитель заказчика", "юрист поставщика").
2. Для каждого определения укажи уровень уверенности (confidence: high/medium/low) и обоснование — конкретную цитату с таймкодом, на основании которой сделан вывод.
3. Если один и тот же реальный человек, вероятно, получил две разные метки (сбой диаризации), укажи это в поле "possible_merge".
4. Если ни имя, ни роль не устанавливаются ни прямо, ни косвенно — верни "identity": null и "role": null, не придумывай.

ФОРМАТ ОТВЕТА (строго JSON, без текста до/после):
{
  "speakers": [
    {
      "speaker_label": "Speaker 1",
      "identity": "Иван Петров" | null,
      "role": "директор по закупкам, сторона заказчика" | null,
      "confidence": "high" | "medium" | "low",
      "evidence": [
        {"quote": "точная цитата из транскрипта", "timestamp": "00:01:23"}
      ]
    }
  ],
  "possible_merges": [
    {"speakers": ["Speaker 2", "Speaker 4"], "reason": "идентичная лексика и самоссылка на ранее сказанное", "confidence": "medium"}
  ],
  "unresolved": ["Speaker 5"]
}

ОГРАНИЧЕНИЯ:
— Каждое определение identity/role должно опираться минимум на одну цитату с таймкодом из evidence. Утверждения без цитаты запрещены.
— Не путай упоминание третьего лица ("Мы вчера говорили с Сергеем из другого отдела") с самопредставлением.
— Если два признака противоречат друг другу (например, спикера называют "Мария", но он говорит "я, как технический директор, Александр..."), зафиксируй противоречие в evidence и понизь confidence до low.
— Не переводи, не исправляй и не сокращай цитаты — копируй буквально из входного транскрипта.
```

**Пример input:**
```
[00:00:05] Speaker 1: Добрый день, коллеги. Начнём. Меня зовут Ирина Соколова, я представляю юридический департамент банка.
[00:00:18] Speaker 2: Здравствуйте, Ирина. С нашей стороны — Дмитрий, коммерческий директор поставщика, и мой коллега подключится чуть позже.
[00:00:33] Speaker 1: Дмитрий, скажите, вы получили обновлённый проект договора?
[00:00:41] Speaker 2: Да, получили вчера вечером. Есть вопросы по пункту 4.2.
[00:01:02] Speaker 3: Прошу прощения, что задержался. Это Артём, технический директор, продолжайте, я на связи.
[00:01:15] Speaker 2: Артём, ты как раз вовремя — мы обсуждаем 4.2, это по срокам поставки.
```

**Пример output:**
```json
{
  "speakers": [
    {
      "speaker_label": "Speaker 1",
      "identity": "Ирина Соколова",
      "role": "юридический департамент банка",

        {"quote": "Меня зовут Ирина Соколова, я представляю юридический департамент банка.", "timestamp": "00:00:05"}

    },
    {
      "speaker_label": "Speaker 2",
      "identity": "Дмитрий",
      "role": "коммерческий директор поставщика",
      "confidence": "high",

        {"quote": "С нашей стороны — Дмитрий, коммерческий директор поставщика", "timestamp": "00:00:18"},
        {"quote": "Артём, ты как раз вовремя", "timestamp": "00:01:15"}

    {
      "speaker_label": "Speaker 3",

      ]
    }
  ],
  "possible_merges": [],
  "unresolved": []
}
```

### B.2. Commitments & action items

**Промпт:**

```
РОЛЬ:
Действуй как бизнес-аналитик и специалист по контроль-менеджменту, отвечающий за фиксацию договорённостей после деловых встреч в крупной организации.

КОНТЕКСТ:
Тебе передан транскрипт переговоров с таймкодами и атрибутированными спикерами (ФИО/роли уже определены на предыдущем шаге). Встреча может касаться коммерческих условий, сроков поставки, юридических согласований или внутреннего проектного статуса. По итогам таких встреч критично зафиксировать все обязательства — явные и неявные, — чтобы не потерять договорённости и иметь возможность проверить их выполнение.

ЗАДАЧА:
1. Найди в транскрипте все обязательства (commitments) — фразы, где кто-либо обещает, берёт на себя ответственность или соглашается сделать что-либо: "я отправлю", "мы подготовим", "давайте я возьму на себя", "договорились, что к пятнице...", а также неявные согласия на предложенное действие ("хорошо, сделаем так" в ответ на предложение).
2. Для каждого обязательства определи: кто берёт обязательство (who), что конкретно обещано (what), к какому сроку (deadline — если назван явно; если срок не назван, используй null и отметь это в comment), уровень уверенности в том, что это действительно обязательство, а не предположение/пожелание (confidence).
3. Не путай обязательство с предложением, которое не было принято ("а давайте вы это сделаете?" без ответного согласия — это не commitment).
4. Отдельно отметь обязательства, которые явно повторяются или уточняются в разных местах транскрипта (например, сначала предложены, потом подтверждены) — считай финальную версию главной, но укажи связанные моменты в "related_mentions".
5. Цитата-опора — реплика, в которой обязательство принято (согласие исполнителя или ответ другой стороны), а не реплика с первым предложением. Предложение без ответа, оборванное согласие, «да» на сказанное несколькими репликами раньше — не commitment, а open question.
6. Для каждого найденного обязательства просмотри остаток транскрипта после его таймкода: не отменено ли, не изменены ли срок, объём или исполнитель. Если изменено — главная версия последняя, прежняя — в "related_mentions" с пометкой «изменено».
7. Если обязательство предлагает или озвучивает ИИ-ассистент (или в транскрипте есть обращение к ИИ с просьбой что-то «записать»), это не обязательство людей без явного принятия участником.

ФОРМАТ ОТВЕТА (строго JSON):
{
  "commitments": [
    {
      "id": "C1",
      "who": "ФИО или роль спикера",
      "what": "точная формулировка обязательства, переформулированная кратко (1 предложение)",
      "deadline": "срок как указан в тексте (например, 'к пятнице', 'до 15 марта') или null",
      "confidence": "high" | "medium" | "low",
      "quote": "точная цитата-источник обязательства",
      "timestamp": "00:00:00",
      "related_mentions": [{"quote": "...", "timestamp": "00:00:00"}],
      "comment": "пояснение при неявном сроке/неуверенности или пустая строка"
    }
  ]
}

ОГРАНИЧЕНИЯ:
— Каждый commitment обязан иметь quote и timestamp — источник в исходном тексте. Никаких обязательств "по смыслу" без прямой текстовой опоры.
— Если срок не назван явно словами говорящего, deadline = null; не пытайся вычислить дату из контекста встречи, если она не проговорена.
— Различай обязательство исполнителя ("мы сделаем") и требование к другой стороне ("вы должны сделать") — оба фиксируются, но роль who всегда — тот, кто ДОЛЖЕН выполнить действие, а не тот, кто его сформулировал.
— Игнорируй общие декларации без конкретного действия ("будем стараться улучшать сервис") — это не action item.
```

**Пример input:**
```
[00:12:04] Дмитрий: По срокам поставки — мы можем взять на себя обязательство отгрузить первую партию до 20 марта.
[00:12:15] Ирина: Хорошо, тогда я подготовлю проект дополнительного соглашения с этой датой и отправлю вам на согласование до конца недели.

[00:13:02] Ирина: Да, конечно, сделаю.
```

**Пример output:**

### B.3. Тактики влияния Чалдини

**Промпт:**

```
РОЛЬ:
Действуй как эксперт по психологии влияния и переговорам, специализирующийся на прикладном анализе диалогов через призму 6 принципов убеждения Роберта Чалдини (взаимность, обязательство/последовательность, социальное доказательство, авторитет, симпатия, дефицит).

КОНТЕКСТ:
Перед тобой транскрипт деловых переговоров с атрибутированными спикерами. Задача — не абстрактная лекция о принципах Чалдини, а прикладной разбор конкретного диалога: кто из участников использовал какую тактику влияния, в какой момент, против кого она была направлена и сработала ли (по реакции собеседника в последующих репликах).

ЗАДАЧА:
1. Для каждого из 6 принципов Чалдини найди в транскрипте конкретные эпизоды, где он применяется:
   — Взаимность (reciprocity): напоминание об одолжении, предложение первым пойти на уступку в обмен на что-то.
   — Обязательство и последовательность (commitment/consistency): апелляция к ранее сказанному собеседником, попытка зафиксировать его на маленьком "да", чтобы потом получить большое.
   — Социальное доказательство (social proof): "все остальные клиенты уже согласились", "на рынке так принято".
   — Авторитет (authority): апелляция к экспертизе, должности, внешним экспертам/регуляторам, статистике.
   — Симпатия (liking): комплименты, поиск общего, неформальный тон для расположения к себе.
   — Дефицит (scarcity): ограниченность предложения по времени/количеству ("это условие действует только до конца месяца").
2. Для каждого найденного эпизода укажи, кто применил тактику (used_by), против кого она направлена (target), и была ли она эффективна — оцени по видимой реакции собеседника в последующих 1-3 репликах (effect: "принято" / "отклонено" / "неоднозначно" / "нет данных").
3. Если принцип в диалоге не встречается вообще — не придумывай эпизод, просто не включай его в вывод (или включи с пустым массивом instances).

ФОРМАТ ОТВЕТА (строго JSON):
{
  "principles": [
    {
      "principle": "reciprocity" | "commitment_consistency" | "social_proof" | "authority" | "liking" | "scarcity",
      "instances": [
        {
          "used_by": "ФИО/роль",
          "target": "ФИО/роль",
          "quote": "цитата, иллюстрирующая приём",
          "timestamp": "00:00:00",
          "mechanism": "краткое объяснение, как именно работает приём в этой цитате",
          "effect": "принято" | "отклонено" | "неоднозначно" | "нет данных",
          "effect_evidence": {"quote": "цитата реакции собеседника", "timestamp": "00:00:00"}
        }
      ]
    }
  ]
}

ОГРАНИЧЕНИЯ:
— Каждый instance должен опираться на прямую цитату. Не приписывай тактику влияния нейтральной деловой фразе без явных признаков приёма.
— Не путай социальное доказательство с обычной ссылкой на факт рынка без манипулятивного контекста — критерий: фраза используется, чтобы подтолкнуть собеседника к решению через отсылку к поведению других.
— effect оценивай только по эксплицитной реакции в тексте (согласие, возражение, смена темы, уступка), не по общей динамике встречи.
— Если один и тот же принцип использован многократно одним спикером — фиксируй все повторения как отдельные instances, это важно для оценки паттерна поведения.
```

**Пример input:**
```
[00:20:11] Дмитрий: Ирина, мы ведь пошли вам навстречу по отсрочке платежа в прошлом квартале. Теперь хотелось бы встречного шага по цене.
[00:20:25] Ирина: Мы это помним и цените вашу гибкость тогда.

### B.5. Манипуляции

**Промпт:**

```
РОЛЬ:
Действуй как эксперт по деструктивным коммуникативным паттернам и переговорной этике, специализирующийся на выявлении манипулятивных тактик в деловых диалогах.

КОНТЕКСТ:
Перед тобой транскрипт деловых переговоров с атрибутированными спикерами. Задача — выявить манипулятивные приёмы (не путать с легитимными тактиками влияния из B.3/B.4 — здесь фокус именно на приёмах, вводящих собеседника в заблуждение или создающих недобросовестное давление):
— Газлайтинг (gaslighting): отрицание ранее сказанного/согласованного, попытка убедить собеседника, что он "неправильно помнит" или "неправильно понял".
— Ложная срочность (false urgency): искусственно созданное давление времени без реального обоснования ("решение нужно прямо сейчас", "иначе сделка сорвётся").
— Якорение (anchoring): изначально называется экстремальное число/условие, чтобы сдвинуть точку отсчёта переговоров в свою пользу.
— Ложный консенсус (false consensus): утверждение, что "все уже согласны"/"это стандартная практика", когда это не подтверждено.
— Тактика "салями" (salami tactics): дробление одного крупного требования на серию мелких, каждая из которых по отдельности выглядит незначительной уступкой.
— Ложная дилемма (false dilemma): искусственное сведение множества вариантов к двум, один из которых явно невыгоден, чтобы вынудить выбрать "выгодный".

ЗАДАЧА:
1. Найди эпизоды каждого типа манипуляции.
2. 4. Будь консервативен: manipulation — это сильное обвинение. Помечай эпизод как манипуляцию только при наличии чётких лингвистических признаков (противоречие с ранее сказанным, непроверяемое обобщение, искусственно навязанная бинарность), а не просто потому, что тактика была настойчивой или неудобной для одной из сторон.

### B.7. Power dynamics (динамика власти в диалоге)

**Промпт:**

```
РОЛЬ:
Действуй как исследователь конверсационного анализа (conversation analysis), специализирующийся на выявлении иерархии и распределения власти в деловых переговорах через лингвистические маркеры.

КОНТЕКСТ:
Перед тобой транскрипт деловых переговоров с таймкодами, атрибутированными спикерами. Власть в диалоге проявляется не через должности, а через конкретные конверсационные паттерны:
— кто инициирует вопросы (а не только отвечает на них);
— кто перебивает других (interruptions) — определяется по обрыву реплики другого спикера до её логического завершения, зафиксированному в транскрипте (например, [00:05] Спикер А: Мы могли бы... [00:06] Спикер Б: Нет, давайте сразу...);
— кто задаёт рамку разговора (framing) — переформулирует повестку, меняет тему, определяет критерии оценки ("на самом деле вопрос не в цене, а в...");
— в каких моментах происходит уступка (concession) — явный отказ от ранее заявленной позиции в пользу позиции другой стороны.

ЗАДАЧА:
1. Посчитай по каждому спикеру: количество инициированных вопросов, количество перебиваний других (как инициатор) и количество раз, когда его перебили (как жертва).
2. Найди все моменты framing — кто и когда переопределил рамку разговора.
3. Найди все моменты явной уступки (concession) — кто, когда, в чём именно уступил.
4. На основе этих сигналов определи доминирующего спикера (dominant_speaker) встречи или её отдельных фрагментов, если доминирование смещается в течение разговора — используй поле "dominance_shifts" для описания смены.

  ],
  "dominant_speaker": {
    "overall": "ФИО/роль или 'сбалансировано'",

ОГРАНИЧЕНИЯ:
— Перебивание фиксируй только если в тексте есть явный признак обрыва реплики (многоточие, обрыв мысли, прямое указание на прерывание) — не считай перебиванием быструю, но полную реплику после короткой паузы.

### B.8. Sentiment / emotional curve

**Промпт:**

```
РОЛЬ:
Действуй как аналитик эмоциональной динамики речи, специализирующийся на количественной оценке эмоционального тона (sentiment/affect) в деловых переговорах на русском языке.

КОНТЕКСТ:
Перед тобой транскрипт деловых переговоров с таймкодами и атрибутированными спикерами. Задача — оценить эмоциональный профиль каждой значимой реплики по двум измерениям модели circumplex affect:
— valence (валентность): от -1 (крайне негативный тон — раздражение, недовольство, отказ) до +1 (крайне позитивный — согласие, энтузиазм, благодарность), 0 — нейтрально;
— arousal (возбуждение/интенсивность): от 0 (спокойная, ровная речь) до 1 (высокая эмоциональная интенсивность — напряжение, спор, воодушевление, стресс).
Дополнительно нужно выявлять явные лингвистические маркеры стресса (паузы/сбои речи, повторы, самоперебивы, резкая смена регистра, повышенная категоричность, извинения без повода).

ЗАДАЧА:
1. Пройди по репликам транскрипта и оцени valence и arousal для реплик, содержащих эмоционально значимый контент (пропускай чисто технические/логистические фразы без эмоциональной окраски, если это явно нейтральный обмен фактами — но включай их с valence≈0, arousal≈0, если это нужно для непрерывности временной кривой).
2. Отметь маркеры стресса (stress_markers) там, где они присутствуют, с указанием конкретного лингвистического признака.
3. Агрегируй оценки в "эмоциональную кривую" по минутам записи (minute_curve) — для каждой минуты, где были реплики, укажи средние valence/arousal по всем репликам этой минуты и укажи, чей эмоциональный вклад доминировал.
4. Не давай психологического диагноза участникам — только описательную оценку тона речи в моменте.

## Чек-лист качества перед использованием отчёта

1. Программная проверка: 100% quote из JSON — точные substring из исходного транскрипта (автоматический скрипт, не LLM).
2. LLM-as-judge прошёл каждый пункт с groundedness score ≥ 4/5, иначе — исключить из отчёта или помечать как "низкая уверенность".
3. Cross-model consistency подтверждена для критичных находок (манипуляции, юридически значимые обязательства).
4. Периодическая (не для каждого прогона, а раз в N транскриптов) сверка с ручной разметкой на golden set для контроля дрифта качества модели/промпта во времени.
