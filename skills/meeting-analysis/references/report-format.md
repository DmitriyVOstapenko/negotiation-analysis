# Формат `report.md`

Автоматический `report_auto.md` создаёт скрипт из 11 артефактов (в лёгком профиле — из 01/07/08, остальное помечено «не выполнялось по профилю»); в разделе «Качество источника» — цитаты, найденные не буквально. Финальный `report.md` —
его отредактированная версия с тем же составом данных и явным разделением слоёв.
Шаблон — `<корень плагина>/templates/report.template.md` (та же структура, что ниже).

Разделы `report_auto.md` идут в порядке скрипта; в `report.md` они раскладываются так:

| `report_auto.md` | `report.md` |
|---|---|
| «Данные:», Один экран | то же, отредактированное |
| Результат, Участники, шапка (Meeting ID, чувствительность, шлюз) | Контекст и источник |
| Ключевые факты, Обязательства: актуальное состояние, Карта решений и полномочий (сказанное) | Факты транскрипта |
| Наблюдённые тактики, Манипуляции, Карта аргументов, Динамика участия, Эмоциональная динамика, Эффективность встречи | Интерпретации и гипотезы |
| Риски: актуальное состояние | Риски |
| Контроль качества, Качество источника | «Данные:» и Что требует проверки |
| Протокол следующей встречи | Для следующей встречи |
| Не выполнялось по профилю (лёгкий разбор) | тот же раздел, перед «Что требует проверки» |

## Структура

```
# <Название встречи> — <дата>
Данные: <транскрипт (провайдер, качество, разметка говорящих есть/нет)>, карта спикеров <подтверждена/предложена>, база на <дата>; чего нет

## Один экран
1. Главный вывод · 2. Требуется решить · 3. Ключевые факты · 4. Риски · 5. Варианты · 6. Следующий шаг

## Контекст и источник
Участники (карта спикеров, статус подтверждения), цель, исход (outcome), исключённые фрагменты,
условия обработки (конфиденциальность, маскирование), качество расшифровки.

## Факты транскрипта
Ключевые факты с цитатами и таймкодами. Обязательства (таблица: кто → кому, что, срок/verbatim,
статус, цитата, таймкод). Открытые вопросы. Решения и ЛПР (из 09) — только сказанное.

## Интерпретации и гипотезы
Тактики (только ≥ probable), манипуляции (≥ probable и severity ≥ medium), аргументация и
карта позиций, динамика власти (с оговоркой о способе подсчёта), эмоциональная кривая
(text_only — с ограничениями), оценка эффективности (формула). Каждый пункт — с confidence.

## Подтверждения пользователя
Что пользователь уточнил после встречи (дата, source: user_confirmation). Не смешивать с
фактами транскрипта.

## Риски
Таблица: риск, тип, severity, likelihood, владелец митигации, срок, цитата. Сначала high.

## Что требует проверки
Выводы с confidence possible/speculative, противоречия, неподтверждённая карта спикеров,
фрагменты плохого качества — всё, что ушло в очередь решений.

## Для следующей встречи
next_meeting_protocol из 11 + не закрытые обязательства обеих сторон.
```

## Правила

- Ничего не добавлять, чего нет в артефактах; если нужно добавить — сначала изменить артефакт и перепройти валидацию.
- Имена — согласно режиму маскирования из шлюза.
- Не выносить в «Факты» то, что в артефактах имеет confidence ниже probable.
- Срок, год которого не назван и взят по дате встречи (`deadline_verbatim` без года), — аналитик добавляет
  в `report.md` пометку «год — по дате встречи»; `report_auto.md` её не ставит. Срок словами без даты
  («до пятницы») — как сказано, без вычисленной даты.
- «Требуется решить» — все решения 09: сначала открытые, затем записанные как принятые (`current_state`
  со статусом «Принято: …», «Решено. …», «Согласовано — …», «Утверждено: …») с пометкой «(записано как
  принятое)»; состояние без статусного префикса — открытое. Так же собирает «Требуемое решение»
  `report_auto.md`.
- ИИ-ассистент — не в списке участников; если он вёл запись или протокол — строкой в «Контекст и
  источник» с тем, что его «фиксации» решениями не считаются.
- Нет разметки говорящих — в «Данные:» и «Контекст и источник»: доли речи не считались, авторство реплик
  выведено по самопредставлению и обращению.
- Длина не ограничена, но первый экран — не длиннее одного экрана.
