# Отправка себе

Решение владельца (2026-10-19): отправлять можно **только себе** и можно отправлять **всё** —
отчёт, брифинг, контрольный центр, обзор контрагента, любой файл рабочей папки.

Другим людям ничего не отправляется: ни коллегам, ни другой стороне. Follow-up для другой стороны
остаётся черновиком (`draft_not_sent`). Человек отправляет его сам из своей почты.

## Каналы

| Канал | Кто отправляет | Что нужно один раз |
|---|---|---|
| Почта | подключение Gmail в Claude: черновик себе, а по прямой просьбе — письмо себе | `deliver setup --email <свой адрес>`; подключение Gmail включено |
| Telegram | скрипт `deliver send` через своего бота | бот у @BotFather, его ключ, привязка личного чата |

Пароли и ключи почты плагин не хранит. Ключ бота Telegram хранится в одном из мест:
- в переменной `NA_TELEGRAM_BOT_TOKEN`;
- в файле `delivery/secrets/telegram_bot_token` рабочей папки;
- в файле `~/.config/negotiation-analysis/telegram_bot_token`.

В отчёты, журнал и ответы ключ не попадает. Если ключ оказался в чате или в чужих руках, перевыпустите его у @BotFather командой `/revoke`.

## Порядок каждой отправки

1. **Показ.** `deliver preview --file <файл> --channel telegram|email`. Пользователь видит одной-двумя строками:
   - куда отправляется: в свой чат или на свой адрес;
   - что отправляется: файл, текстом или файлом, сколько сообщений;
   - предупреждения: встреча помечена `local_only` или как конфиденциальная, этот текст уже отправлялся.
2. **Явное «отправить».** Одобрить текст — не значит согласиться на отправку. Не отправляйте, пока человек не сказал «отправь»,
   «да, в телеграм» или похожее именно об отправке.
3. **Отправка.**
   - **Telegram:** `deliver send --file <файл> --confirm`. Скрипт сверяет содержимое с показом по отпечатку. Если файл изменился, нужен новый показ.
   - **Почта:**
     1. Создайте через подключение Gmail черновик: адресат — только адрес из показа, тема — из показа, текст — содержимое файла. Копий и других адресатов не бывает.
     2. Отправлять письмо сразу можно только по прямой просьбе «отправь письмо».
     3. После этого: `deliver record --file <файл> --status draft|sent [--ref <id>]`.
4. **Итог одной строкой.** «Отправил себе в Telegram, 2 сообщения», «Черновик себе в Gmail». Если отправка не прошла, назовите причину.

## Повторы и неизвестный исход

- **Тот же текст уже отправлен.** Скрипт откажет. Ещё одну копию отправляйте только по просьбе человека, с флагом `--again`.
- **Исход неизвестен** (связь оборвалась после отправки) **или отправлено частично.** Не повторяйте. Попросите проверить чат. Если сообщения там нет, повторите с флагом `--resend-unknown` после ответа человека.
- **Почта: исход неизвестен.** Запишите `deliver record --status unknown` и попросите проверить черновики или отправленные.

## Без человека не отправляется

- **Запуск по расписанию или фоновый.** Команды `send` и `record --status sent` не выполняются. Материал готовится, показ делается, а пользователю приходит сообщение «готово к отправке себе: …».
- **Каналы не настроены** (`deliver status`). Отправку не предлагайте. Если человек сам попросит, расскажите, как настроить.

## Где это работает

- **Claude Code и Cowork, папка на компьютере.** Работают оба канала.
- **Облачный режим.** Telegram — если сеть разрешает `api.telegram.org`. Если сеть закрыта, скажите об этом прямо и предложите почту или файл.
- **Проект claude.ai.** Скриптов нет, поэтому:
  - Telegram недоступен;
  - почта работает, если подключение Gmail включено: черновик себе;
  - журнал не ведётся — скажите об этом одной фразой.

Скрипты выходят в сеть только здесь: `deliver telegram-link` и `deliver send` обращаются к API Telegram. Остальные команды
плагина в сеть не ходят.

## Первая настройка Telegram

1. Создайте бота: в Telegram откройте @BotFather → `/newbot` → придумайте имя → получите ключ.
2. Передайте ключ скрипту так, чтобы он не попал в историю команд и в файлы рабочей папки, кроме `delivery/secrets/`:
   ```bash
   python3 "<корень плагина>/scripts/na.py" --root <рабочая папка> deliver setup --telegram-token-stdin
   ```
   Ключ подаётся одной строкой на стандартный ввод. Можно и проще: самому положить его в `delivery/secrets/telegram_bot_token`
   или задать переменную `NA_TELEGRAM_BOT_TOKEN`.
3. Со своего аккаунта откройте бота и нажмите «Старт».
4. Выполните `deliver telegram-link`: скрипт покажет личные чаты, которые писали боту. Затем привяжите свой чат:
   `deliver telegram-link --chat <id> --confirm`.
   Группы и каналы не привязываются. Отправка идёт только в привязанный личный чат.

Почта: `deliver setup --email <свой адрес>`. Сменить адрес или отвязать Telegram можно ключами `--email`, `--forget-email` и `--forget-telegram`.

## Журнал

`delivery/journal.jsonl` только дописывается. В каждой записи:
- время;
- канал;
- адресат (всегда «себе» и сам адрес или чат);
- файл;
- отпечаток содержимого;
- режим;
- сколько частей ушло;
- исход: `sent`, `draft`, `failed`, `unknown` или `partial`.

Посмотреть журнал: `deliver log`. Папка `delivery/` не отправляется и не попадает в пакеты разбора.
