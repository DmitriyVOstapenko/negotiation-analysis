# Шлюз нового источника

Применяется к каждому новому SourceArtifact с персональными, голосовыми, биометрическими
или специальными категориями данных — отдельно для каждой записи, даже если автор или
участники те же.

## Порядок

1. **Классифицировать** источник: запись / транскрипт / документ / таблица / переписка /
   подтверждение пользователя / другое. До прохождения шлюза содержание не разбирать
   (допустимо заглянуть в первые строки, чтобы понять тип и наличие таймкодов).
2. **Задать вопросы одним блоком** (не растягивать на несколько ходов):

   > Прежде чем разбирать запись, зафиксирую условия обработки:
   > 1. Право на обработку: участники уведомлены о записи / есть согласие / это внутренняя
   >    встреча вашей организации / основания нет?
   > 2. Конфиденциальность: public / internal / confidential / regulated?
   > 3. Категории данных: только деловая речь / персональные данные третьих лиц / голос /
   >    биометрия / специальные категории (здоровье и т.п.)?
   > 4. Маскирование: без маскирования / инициалы / псевдонимы / полное обезличивание?
   > 5. Маршрут: допустима обработка облачной моделью (как сейчас) / только локально?
   > 6. Хранить исходный транскрипт в базе после анализа: да / нет?

   Если профиль `policy.yaml` задаёт значения по умолчанию — предложить их как вариант, но
   получить явное подтверждение для этой записи.
3. **Зафиксировать** ответы: `na.py source gate --meeting <id> --consent … --masking … --sensitivity … --routes … --retain-source …`.
   Они попадают в `review.yaml` и `source_packet.json`.
4. **Если согласия нет или маршрут запрещает облачную обработку** — остановиться:
   источник остаётся `blocked_by_gate`; предложить четыре маршрута: явно разрешённый
   внешний сервис, обезличенная производная (пользователь сам маскирует и передаёт
   заново), только локальная обработка (вне этого разговора), отложить.
5. **Маскирование** применяется ко всем артефактам и отчётам: при `initials` — «Иванов И.»
   → «И. И.», при `pseudonyms` — устойчивые псевдонимы «Участник A/B/C» с картой
   соответствия только в `review.yaml`, при `full` — без имён, ролей-идентификаторов и
   названий организаций.

## Что не наследуется

Решение по одной записи не переносится на следующую. Согласие на запись не означает
согласия на хранение аудио. Временная подписанная ссылка на аудио не сохраняется.

## Хранение

- `retain_source: yes` → `transcript.txt` остаётся в `negotiations/<id>/` и в проекте.
- `retain_source: no` → после анализа транскрипт удаляется из хранилища; цитаты в
  артефактах остаются (они — доказательства), повторная проверка цитат будет невозможна —
  сказать об этом пользователю.
- Удаление у одного провайдера не означает удаления копии у другого — не обещать «удалено
  везде».
