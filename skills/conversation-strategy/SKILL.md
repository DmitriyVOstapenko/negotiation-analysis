# Стратегия сложного разговора

Связка двух навыков этого плагина: **факты** — из накопительной базы (`knowledge/`,
`negotiations/`) и слов пользователя; **метод** — встроенный навык `negociar-ru` (русская
адаптация Negociar Арти Галиева, традиция В. Тарасова; канон из 275 принципов и библиотека
реальных разборов). Метод даёт интерпретацию и ходы, но не создаёт фактов о людях и событиях.
Правила границы — `references/strategy-advisory.md`.

Если вопрос не касается людей и встреч из базы («как ответить хейтеру», «как попросить
повышения») — достаточно самого навыка `negociar-ru`; этот навык нужен, когда стратегию надо
опереть на накопленные факты.

## 1. Метод — встроенный `negociar-ru`

> **Пути.** Claude Code сам подставляет путь к плагину вместо переменной `CLAUDE_PLUGIN_ROOT` (со знаком доллара и в фигурных скобках) в тексте этого файла. Если в команде переменная осталась как есть (другой хост) или команда взята из справочного файла (там написано `<корень плагина>`), подставь путь сам: корень плагина — на два уровня выше каталога этого навыка (`Base directory for this skill` → `…/skills/<навык>` → корень). Переменная окружения в Bash пуста — не полагайся на неё.

Полностью прочитать `${CLAUDE_PLUGIN_ROOT}/skills/negociar-ru/SKILL.md` и работать по его
контракту: четыре блока (реальная ситуация и слепая зона · что это по канону · лестница ходов
вопросами, с возражениями, ответами и худшим сценарием · развилки по недостающим данным), до
трёх уточняющих вопросов в конце. Канон и случаи читать его способом:

```
python3 ${CLAUDE_PLUGIN_ROOT}/skills/negociar-ru/scripts/buscar.py "слова ситуации" --dom D3,D8 --n 6
python3 ${CLAUDE_PLUGIN_ROOT}/skills/negociar-ru/scripts/buscar.py --show <N>
python3 ${CLAUDE_PLUGIN_ROOT}/skills/negociar-ru/scripts/buscar.py --canon D4
```

Поиск понимает русские слова в любой форме; вся библиотека переведена (поле
`translation_status` — уровень проверки перевода). При слабом результате переформулировать
запрос другими словами ситуации или снять фильтр домена. Не подменять канон общими советами по переговорам; если канон чего-то не покрывает —
сказать об этом.

## 2. Перед разбором — факты отдельно от стратегии

- Собрать из базы и слов пользователя: кто участники (роли, полномочия — подтверждённые),
  история (обязательства, решения, прошлые позиции с датами), что уже сказано другой стороне
  и каким каналом, ограничения пользователя («не признавать вину письменно», «только звонок»),
  чего он хочет и чего боится, временная точка и окно действия. Хранилище и чтение базы —
  по `negotiation-system/references/store-adapter.md`.
- Прочитать `knowledge/strategies/*/index.jsonl` — карточки `approved_for_reuse` по тем же
  людям/темам и их `StrategyOutcome`; прошлая стратегия — не новый факт.
- Перечислить пробелы и противоречия. Если контекст может перевернуть ход — спросить
  (без ограничения числа вопросов для понимания ситуации; «до трёх» — только для финальной
  донастройки).

## 3. Формат результата

Сначала короткий управленческий вывод (1–3 абзаца), затем **в том же ответе** полный разбор
по контракту `negociar-ru`, с явным разделением:

1. подтверждённые факты и их источники (встреча, цитата, таймкод, карточка базы);
2. выводы из фактов (реальная картина без макияжа, включая слепую зону пользователя —
   мягко по форме, твёрдо по сути);
3. рабочие гипотезы и альтернативные объяснения;
4. применимый принцип канона — объяснённый простыми словами до названия;
5. последовательность ходов — вопросами, не монологом; для каждого шага: цель, что
   затронуть и почему, вероятные ответы другой стороны, ваш ответ на каждый;
6. худший сценарий и обратимый деловой (не личный) ход;
7. неизвестные, способные изменить стратегию.

Обязательно: временная точка и окно; вероятные возражения и ответ на каждое; фиксация
(цифра, дата, письменно) на каждом шаге. Язык — простой, без жаргона и кодов.

**Проверять всегда при ошибке своей стороны, жалобе, извинении:** вину не признавать
письменно (сначала действия, извинение — голосом); никакой «дешёвой эмпатии» («понимаем,
как вам тяжело»); не оправдываться раньше времени; не обещать лишнего письменно.

## 4. Текст сообщения — только по прямой просьбе

Дословный текст составлять, только если пользователь прямо попросил («напиши сообщение»,
«дай точный текст»). Перед этим спросить: что уже сказано лично/голосом/письменно; какие
признания, обещания, темы нельзя включать; канал и тон. Результат — черновик
`draft_not_sent` для проверки пользователем, не финальный текст; ничего не отправлять.

## 5. Сохранение и результат

После полного разбора спросить: сохранить полностью / выбранные выводы / только архив /
не сохранять. До ответа файлы не менять. Сохранение — `advice/negociar-ru/<strategy_id>/`
(карточка) + при `approved_for_reuse` запись в `knowledge/strategies/negociar-ru/index.jsonl`;
в режиме проекта — `project_write`. Интерпретации в карточки людей не переносить — только
факты с EvidenceRef через `knowledge-update`.

Когда пользователь расскажет, чем закончился разговор, — предложить `StrategyOutcome`
(фактические действия, реакция другой стороны, что сработало, уроки) со связью `supersedes`
к карточке; режим повторного использования (`keep / strengthen / weaken / retire`) — только с
его подтверждения.

## Режим тренировки

По просьбе («сделай role-play», «побудь моим контрагентом») — режим тренировки из
`negociar-ru`: играть другую сторону реалистично и с давлением, после каждого обмена давать
разбор в стиле Арти — какой захват принят, какая пустота оставлена, какой ход был бы сильнее,
с принципом и случаем. Фактуру роли брать из базы.

## Чего не делать

- Не выдавать принцип, случай или интерпретацию за факт о человеке.
- Не ставить диагнозов и не вешать ярлыков.
- Не писать текст сообщения по собственной инициативе и не отправлять его.
- Не записывать стратегию в базу без выбора пользователя.
- Не ссылаться на случай, который не прочитан через `buscar.py --show`.
- Не предлагать подкуп, «подарки» должностным лицам и сокрытие следов, даже если на это похож
  принцип или случай канона (05 #8, случай 400): назвать риск и строить законный ход.
