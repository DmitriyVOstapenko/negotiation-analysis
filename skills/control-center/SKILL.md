# Контрольный центр и очередь решений

Один экран того, что требует внимания руководителя, — из канонических реестров, а не из
прошлого отчёта. Правила доказательности и хранилище — навык `negotiation-system`.

## Порядок

**1. Хранилище.** Определить режим (`store-adapter.md`). В режиме проекта загрузить в `ROOT`
все `knowledge/**/*.jsonl`, `knowledge/review_decisions.jsonl`, `knowledge/index.md` и,
если вопрос про людей/компании/темы, соответствующие карточки; для «что изменилось после
встречи» — `negotiations/<id>/knowledge_diff.md`, `run_manifest.json`.

**2. Пересобрать производные.** Всегда перед ответом о состоянии:
```
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/na.py --root ROOT refresh-all
```
Затем читать `ROOT/system/control_center.json` (или `.md`) и `ROOT/system/review_queue.json`.
Ошибки целостности (дубликат id, запись одновременно в open и closed, ссылка на
несуществующую сущность) показать пользователю первыми. Предупреждения — отдельно.

**3. Ответить по блокам** (`references/control-center-format.md`), показывая только то, что
требует внимания:
1. **Решить сейчас** — открытые пункты очереди (`review_queue`), решения с дедлайном,
   критические противоречия; для каждого: формулировка, почему сейчас, владелец, срок,
   доказательство, следующий шаг.
2. **Исполнение** — просроченные и заблокированные поручения и обязательства, результаты
   без доказательства, повторные переносы.
3. **Инициативы** — отклонения, только если параметры подтверждены.
4. **Риски и возможности** — критические активные, материализовавшиеся, закрывающиеся окна.
5. **Обязательства** — что должны мы и что должны нам, ближайшие сроки (14 дней).
6. **Люди и позиции** — только подтверждённые существенные изменения.
7. **Качество данных** — противоречия, неизвестные исполнители/сроки, непроверенные выводы.

Приоритет: необратимость и ущерб → срочность → стратегическая значимость. Не называть
объект критическим без основания. База пуста — сказать прямо, демонстрационных данных не
придумывать.

**4. Очередь решений — отвечать коротко.** Для каждого пункта пользователь отвечает «да»,
«нет», имя, срок или статус. После каждого ответа:
```
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/na.py --root ROOT review record --item <rq-id> --decision "<ответ пользователя>" [--status closed|deferred]
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/na.py --root ROOT refresh-all
```
Показать зафиксированное изменение и предложить следующий открытый пункт. Закрытие
обязательства или риска по ответу пользователя — через `knowledge-update` (proposal с
`action: close`), не напрямую. В режиме проекта после записи — `project_write` изменённых
реестров.

## Типовые запросы

- **«Что требует моего решения сейчас?»** → блок 1 + первые три пункта очереди с вопросами.
- **«Какие обязательства нужно проверить на этой неделе?»** → обязательства со сроком в ближайшие 7–14 дней и просроченные; контрольная дата не заменяет исходный срок — показывать обе.
- **«Что мы знаем об X?»** → карточка `knowledge/people/` или `organizations/` + открытые обязательства и риски с участием X + наблюдённые тактики (только ≥ 2 встреч). Разделять факты, наблюдения и гипотезы. Нет карточки — сказать «в базе нет».
- **«Найди все решения и цитаты по теме Y»** → `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/na.py --root ROOT search "Y"` — цитаты с встречей и таймкодом, решения, аргументы.
- **«Что изменилось после этой встречи?»** → `knowledge_diff.md` встречи + события журнала с этим `meeting_id`.
- **«Какие выводы уже устойчивы, а где данных мало?»** → по порогам (`evidence-rules.md`): паттерн — ≥ 2 встречи; с одной встречей — «недостаточно данных».
- **«Продолжи незавершённую встречу»** → `na.py status` → первая встреча с `resume_from` ≠ null → навык `meeting-analysis` с нужного шага.

## Чего не делать

- Не закрывать обязательства, риски, пункты очереди без явного решения пользователя.
- Не менять `system/*`, `ledger.jsonl`, `run_manifest.json` вручную — только через скрипты.
- Не объявлять «всё в порядке», если `refresh-all` вернул ошибки целостности.
- Не показывать всю базу, когда спросили «что требует внимания».
