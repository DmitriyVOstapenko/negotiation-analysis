# negotiation-analysis — накопительная система анализа переговоров

> **v0.7.0** · плагин для Claude (Claude Code, Cowork, проекты claude.ai) · по-русски · без внешних сервисов (кроме отправки себе, если включите) ·
> встроенный советник по переговорам **Negociar-RU** (русская адаптация канона Арти Галиева, традиция В. Тарасова)

Вы даёте транскрипт встречи. Система разбирает его по одиннадцати проверяемым артефактам (лёгкий разбор — по трём) —
участники и факты, обязательства, риски, тактики, манипуляции, аргументация, динамика
власти, эмоциональная кривая, карта решений и ЛПР, карта позиций, оценка эффективности, —
проверяет каждую цитату по транскрипту, показывает один управленческий экран и
**предлагает** изменения накопительной базы. Вы подтверждаете — база растёт. Следующая
встреча начинается с брифинга: кто эти люди, что обещали, где риски, что спросить.

Это система для руководителя, которая работает только с доказательствами: неизвестное
остаётся неизвестным, статусы не закрываются сами, другим людям ничего не отправляется (себе —
только по вашему «отправить»), диагнозы не ставятся.

## Что внутри

| Навык | Что делает |
|---|---|
| `negotiation-system` | Общие правила: доказательность, шлюз согласия на обработку записи, выбор хранилища (папка / проект claude.ai), маршрутизация. Загружается первым. |
| `meeting-analysis` | Разбор встречи: шлюз → регистрация источника → карта спикеров → 11 артефактов (лёгкий разбор — 3) → строгая проверка схем и цитат → отчёт с одним экраном → follow-up (черновик, не отправляется) → проект изменений базы. |
| `knowledge-update` | Обновление базы: проект изменений с полным учётом (у каждого обязательства, риска, решения — одна судьба) → diff → ответы по сомнительным пунктам → явное подтверждение → запись с журналом событий. Ручные пометки `(m)` неприкосновенны, история не удаляется. |
| `control-center` | «Что требует моего решения?»: обязательства, просрочки, зависшие вопросы, риски, очередь решений, поиск по цитатам, «что мы знаем о …». |
| `executive-briefing` | Брифинг на одну страницу перед встречей, повестка своей встречи, обзор контрагента за период (что обещали и чем подтверждено), экстренный брифинг, недельный и месячный обзоры, пакет к совету директоров, поддержка решения, сравнение встреч. |
| `conversation-strategy` | «Как на это ответить» по людям и встречам из базы: факты — из базы, метод — встроенный `negociar-ru`; текст сообщения — только по прямой просьбе и только как черновик. |
| `negociar-ru` | Советник по коммуникации, управлению людьми, продажам и переговорам: канон из 275 принципов и библиотека из 1019 реальных разборов — всё на русском (русская адаптация Negociar, CC BY-NC-SA 4.0). Реконструирует ситуацию, показывает слепую зону, строит лестницу ходов с возражениями и худшим сценарием. |

Плюс: онтология (`core/ontology/`), исполняемые контракты (`core/contracts/`), профили роли /
организации / политик (`profiles/`), детерминированные скрипты (`scripts/na.py`), шаблоны,
субагенты для длинных встреч и независимой проверки (`agents/`), хук защиты базы (`hooks/`),
синтетический сквозной тест и проверочные встречи с оценкой разбора (`tests/`, `docs/EVALS.md`).

## Как это выглядит

> **Вы:** Вот транскрипт вчерашней встречи с поставщиком (вставлен текст с таймкодами).
> Наши — я и юрист. Цель была — согласовать перенос сроков без штрафов.
>
> **Система:** Прежде чем разбирать запись, зафиксирую условия обработки: право на запись
> есть? уровень конфиденциальности? маскировать имена? хранить транскрипт в базе? …
>
> **Вы:** Внутренняя встреча, участники уведомлены, confidential, без маскирования, хранить.
>
> **Система:** Карта спикеров: Speaker 1 — вы (самопредставление в 00:00:40), Speaker 2 —
> Ирина, юрист (обращение по имени 00:03:12), Speaker 3 — Сергей, поставщик (confidence:
> probable — представился только фамилией). Подтвердите или поправьте. … 11 артефактов
> прошли проверку: 47 цитат найдены в транскрипте.
>
> **Один экран.** Исход — partial. Решение о переносе срока не принято: ЛПР со стороны
> поставщика не назван (00:41:10 «надо согласовать с руководством»). Три обязательства:
> Сергей — прислать новый график до пятницы (00:38:05); вы — направить проект допсоглашения
> (00:39:20); Ирина — проверить штрафные условия (00:40:02). Риск high: срок поставки
> сдвигается без письменной фиксации. Требует вашего решения: 2 пункта. Подготовлены детали:
> тактики (3), манипуляции (0 выше порога), аргументация, динамика власти, карта решений.
> Раскрыть?
>
> **Вы:** Применяй изменения базы.
>
> **Система:** Добавлено: 1 человек, 1 организация, 3 обязательства, 1 риск; обновлена тема
> «Поставка партии 2». В журнал записано 4 события (обязательства и риск). В очереди решений 2 пункта. Следующий: подтвердить
> роль Сергея — он ЛПР или нет?

## Установка

### Claude Code

```
/plugin marketplace add DmitriyVOstapenko/negotiation-analysis
/plugin install negotiation-analysis@negotiation-analysis-marketplace
```

Требуется Python 3.10+ в `PATH` (`python3`). Внешних зависимостей нет.

### Cowork / проекты claude.ai

Установить из файла `negotiation-analysis.plugin` (кнопка принятия в чате) или из каталога
плагинов организации, если плагин туда добавлен. База знаний в проекте claude.ai живёт в
документах проекта; в Cowork — в подключённой папке. Подробности —
`docs/INSTALL.md`.

### Советник Negociar-RU — уже внутри

Отдельно ничего ставить не нужно: русская адаптация Negociar встроена в плагин как навык
`negociar-ru` (канон, библиотека случаев, поиск на Python). Оригинал на испанском —
https://github.com/arturgaliev3099-ux/realmanagement — для работы не нужен. Если он у вас
установлен отдельно, навыки этого плагина его не используют.

## Как пользоваться

Говорите обычными словами:

- «Проанализируй встречу» + транскрипт (или файл, или запись из подключённого источника)
- «Что требует моего решения сейчас?»
- «Какие обязательства нужно проверить на этой неделе?»
- «Подготовь брифинг к встрече с … по теме …»
- «Что мы знаем о …?» / «Найди все цитаты по теме …»
- «Что изменилось после этой встречи?»
- «Как на это ответить?» / «Разбери ситуацию с …»
- «Подготовь протокол и письмо, но не отправляй»
- «Дай недельный обзор» / «Месячный обзор»
- «Только обязательства и риски» — лёгкий разбор
- «Что обещал нам … за квартал и чем это подтверждено?» — обзор контрагента
- «Пришли отчёт себе в телеграм» — отправка себе (после настройки)
- «Проверь установку» — самопроверка `na.py doctor`

## Где живёт база

```
<корень>/
  profile/        role.yaml, organization.yaml, policy.yaml     (опционально)
  negotiations/   <дата-slug>/ — транскрипт, review.yaml, analysis/*.json, report.md, follow_up.*
  knowledge/      people/, organizations/, topics/, commitments/, risks/, decisions/, events/ledger.jsonl …
  system/         производное — пересобирается, не хранится
```

Корень — папка (Claude Code / Cowork) или документы проекта claude.ai с теми же путями.
Источники истины — `negotiations/`, `knowledge/`, `profile/`, `review.yaml`.
Всё, что в `system/`, можно удалить и пересобрать: `python3 scripts/na.py --root <корень> refresh-all`.

## Инварианты

1. Сырые источники после фиксации границ не меняются.
2. Любой существенный вывод содержит цитату, таймкод и уверенность.
3. Подтверждение пользователя не выдаётся за фразу из транскрипта.
4. Производное представление можно удалить и полностью пересобрать.
5. Один идентификатор не может быть одновременно активным и закрытым.
6. Ручные пометки `(m)` не перезаписываются автоматически.
7. Ошибка схемы, цитаты или проекции блокирует статус `ready`.
8. Открытый вопрос и незавершённый анализ — разные состояния.
9. Аудиометрики — не детектор лжи, намерений или манипуляций.
10. Контрольная дата не заменяет исходный срок обязательства.

## Что происходит на вашей машине

Скрипты (`scripts/`, `skills/negociar-ru/scripts/`) читают и пишут только в указанный корень
базы и в каталог плагина; поиск по случаям только читает свои данные.
В сеть ходит только отправка себе в Telegram через вашего бота: привязка своего чата и отправка
по вашему «отправить». Ключей в файлах плагина нет; ключ бота хранится у вас (`delivery/secrets/`,
переменная окружения или `~/.config/negotiation-analysis/`). Хук плагина не даёт модели писать в базу в обход подтверждения. Опциональный аудиоанализ требует
отдельных библиотек и честно сообщает, если их нет. Интеграции с источниками записей
(PLAUD, WonderScribe, локальная транскрипция) — следующие версии; сейчас транскрипт
передаётся вручную.

## Приватность

Перед каждой новой записью с персональными или голосовыми данными система задаёт шлюз:
право на обработку, конфиденциальность, категории данных, маскирование, маршрут, хранение.
Без согласия запись не анализируется. Реальные встречи и база пользователя в репозиторий не
входят и никогда не входили. См. `docs/PRIVACY.md`.
